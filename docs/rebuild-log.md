# PCoM-DB 再構築 作業記録（2026年11月）

PCoM-DB（タンパク質共移動データベース）を Rails 7.1 から Rails 8.1 へ作り直した記録です。
技術ブログの素材として、判断の理由も残しています。

---

## 0. 背景

- 運営はボランティアで、保守の手間をできるだけ減らしたい。
- 最終更新は2023年6月。Rails 7.1 のサポートが2025年10月に終わっていた。
- 方針：「DB はそのまま」「URL・画面・機能はそのまま」「保守を自動化」。

## 1. 現状診断（第1段階）

本番サイトへのアクセスは最小限（数回）にし、主にソースコードとバックアップで調べた。

| 項目 | 結果 |
|---|---|
| brakeman（コードの静的解析） | Rails 7.1 のサポート終了の警告 1件のみ。SQLインジェクション・XSS は検出なし |
| bundle-audit（依存 Gem の既知の脆弱性） | **246件**（Critical 1 / High 30 / Medium 58 / Low 23 / 不明 134） |
| 本番ヘッダ | TLS 1.3、HSTS、Cookie の secure / httponly / samesite は OK。**CSP なし** |
| JavaScript ライブラリ | jQuery 1.8.2（2012年）、Highcharts 4.0.3（2014年）、Lightbox 2.7.1 |
| リポジトリ | `config/master.key` と `credentials.yml.enc`、SQLite の DB ファイル、ログ、`node_modules`（約1.4万ファイル）がコミットされていた |

学び：

- `.gitignore` に書いても、**すでにコミット済みのファイルは追跡され続ける**。
- コードの書き方（SQL のプレースホルダ、ERB の自動エスケープ）は丁寧だったが、
  **フレームワークとライブラリの放置**が脆弱性の大半を占めていた。

## 2. バックアップの確認

- Heroku のダッシュボード（Durability タブ）から手動バックアップを取得。
- バックアップは PostgreSQL 17 の形式（アーカイブ形式 1.16）だったため、作業環境の
  `pg_restore`（16）では読めなかった。形式を直接読む小さな Python スクリプトを書いて展開し、
  PostgreSQL 16 に復元して中身を確認した。
- 13 試料すべてのデータを確認（msresults 712,250 行、proteins 97,690 行）。

## 3. 見つかったバグ（本番で起きていたもの・起こり得たもの）

1. **メニューの背景画像などが表示されていなかった**
   CSS が `url(/assets/btn1.png)` と固定パスで画像を指定していた。
   Rails 4 以降、アセットはダイジェスト付きのファイル名（`btn1-5e26….png`）でしか出力されないため 404 に。
   メニュー以外にも、見出しの装飾、表の並べ替え矢印、トップページの背景画像、Overview の拡大画像が同じ原因で表示されていなかった。
2. **Help ページの PDF リンク**：リンク先のアクション（`helpdoc` など）にルートがなく、
   コード上はリンク生成の時点でエラーになる状態だった（本番での発生は未確認）。→ `public/excel/` の PDF に直接リンク。
3. **symbols 検索結果のリンク**：`GET /proteins/search_protein?gene_id=…` のルートがなく、
   クリックすると 404 だった。→ GET ルートを追加。
4. **複数検索で BP-1 を選ぶと色が付かない**：`gel64_*` の CSS クラスが未定義だった。→ 追加。
5. **パラメータが欠けると 500 エラー**：`gene_id_str` なしの getchart、`symbols` なしの検索など。→ すべて 404 か通常表示に。
6. **相同タンパク質の BP-1 行**：表示用の変数が未設定のまま参照する箇所があった（現データでは該当なし）。

## 4. 設計の判断

| 判断 | 理由 |
|---|---|
| Rails 8.1 で新規に骨組みを作り、コードを移植 | 7.1 → 8.1 の段階的アップグレードより、小さなアプリでは作り直しの方が確実で、不要な設定が残らない |
| **DB には一切変更を加えない** | 本番データを守るため。マイグレーションは置かず、`db/schema.rb` は本番のコピーから出力 |
| Webpacker・jQuery・Lightbox を廃止 | 依存ライブラリを減らす＝今後の更新作業を減らす。必要な処理は約300行の素の JavaScript（`pcom.js`）に置き換え |
| Highcharts は最新版（12.x）を同梱 | グラフの見た目と操作性を維持するため |
| インラインの `onclick` や `<script>` をすべて排除 | 厳格な CSP（`script-src 'self'`）を有効にするため。XSS があっても外部スクリプトを実行させない |
| 表の並べ替え（TINY.table.sorter）を書き直し | 元のコードは `new Function()` を使っており、厳格な CSP では動かないため |
| 1,000 行のコントローラを約 220 行に | `@msresults1`〜`30` のような繰り返しを、試料の一覧（`Material::ARABIDOPSIS_ROWS` など）による表示に変更 |
| `allow_browser`（古いブラウザを拒否する Rails 8 の既定）を外した | 研究者が古いブラウザで見ても閲覧できるように |
| 本番のホスト名を限定（`config.hosts`） | Host ヘッダ偽装・DNS リバインディング対策 |

## 5. 入力値の扱い

- 遺伝子 ID：前後の空白と全角空白を除去し、小文字化（旧サイトではブラウザ側だけで行っていた処理をサーバ側でも実施）。
- 64 文字を超える遺伝子 ID は無視する。グラフに重ねる遺伝子は最大 10 件までに制限（旧サイトはブラウザ側でのみ制限）。
- LIKE 検索の `%` や `_` は文字として扱う（`sanitize_sql_like`）。
- 存在しない試料 ID・遺伝子 ID は 404 を返す。

## 6. CSRF とグラフのクリック

グラフの点をクリックすると、同じフォームを別の URL（`getchartlist`）に送信する。
Rails は既定でフォームごとに URL に紐づいたトークンを使うため、送信先を変えると拒否される。
旧サイトはこの画面の CSRF 検証を外して対処していた。
新しい版では、このフォームだけ**セッション共通のトークン**を使うことで、検証を外さずに解決した。

- バックアップから復元した DB に接続し、ブラウザ（Playwright）で全画面を操作：
  一覧・ページ送り・並べ替え・グラフ・点クリック・reCharts・表示モード切替・各種検索・画像拡大・PDF。

  全アセットの読み込みを確認。
- 自動テスト 19 件、brakeman 警告 0、bundle-audit 0 件。

## 8. 見た目の調整（リンクのデザイン）

- グラフ画面の外部リンク（TAIR、KEGG など）は見出し（`<h1>`）の中にあったため、見出しと同じ大きさの太字で、
  青い下線付きで表示されていた。これが古く見える原因だった。
- 3案を実際の画面に当てはめて比較し、**案C（控えめなテキストリンク）** を採用：
  - 外部リンクは小さな緑の文字で「・」区切り、外部サイトを示す「↗」付き。「link to」の文言は省略。
  - 一覧の遺伝子IDは濃い緑の等幅フォント、下線はマウスを乗せたときだけ。行全体も淡い緑で強調。
  - normal / max100% の切り替えも、薄すぎた灰色（#e0e0e0）から読める緑に。
- トップの表記を「Ver 2.2　last update:2026.11.16」に更新。

### gel_no / MW の表が空になる試料について

不具合ではなく、データの有無によるもの。分子量マーカーのデータ（materialweights）は
chloroplast、chloroplast 2、stroma、envelope の4試料には登録がなく、残りの9試料にだけある（マーカー4〜7か所）。

### 手元の確認で引っかかったこと（メモ）

production モードの確認で `assets:precompile` した `public/assets/` が残っていると、
開発サーバーがそちらを優先して配信し、CSS の変更が反映されないように見える。確認後は削除すること。

## 9. 照合テスト（第3段階）

### 手元での全件照合
旧コントローラの計算処理をそのまま写したスクリプトと、新しいアプリが返す HTML を、復元したバックアップで比較した。

| 対象 | 件数 | 不一致 |
|---|---|---|
| 色分けレベル（遺伝子×試料の全組み合わせ） | 11,708 | 10 |
| 試料ごとの一覧（13試料） | 13 | 0 |
| 一覧の symbols 表示 | 650 | 0 |
| グラフの値（各試料40遺伝子 × 2モード） | 1,040 | 6 |
| 複数遺伝子の重ね描き | 13 | 0 |
| ピークリスト（全試料の全 gel スライス） | 777 | 0 |
| 単一検索（相同タンパク質を含む） | 390 | 0 |
| 複数検索（大文字小文字・存在しない ID を含む） | 39 | 0 |

不一致はすべて、次の「並び順の不具合」によるもの。

### 旧サイトの不具合：gel の並びがずれていた10件
DB 上で行の保存順が gel 番号順になっていない組み合わせが10件あった（例：thylakoid の AT5G60250 は 57, 58, 59, 60, 1, 2, …）。
旧コードは `ORDER BY` なしで取得していたため、これらの遺伝子では**グラフと色分けの帯が途中で折り返して表示**されていた。
新しいコードは gel_no 順に並べるので正しく表示される（再発防止のテストも追加）。

対象：AT1G03110（chloroplast 2）、AT1G27680・AT1G64510・AT3G22380・AT5G16715・AT5G36700（stroma）、
AT5G60250（thylakoid）、sll1388・sll1813・slr0338（PCC6803）

### 本番との照合（34回のアクセス、2秒間隔）
- 一覧 13試料：すべて一致
- グラフ 10件：7件一致。残り3件は上記の並びのずれで、**本番で実際にずれて表示されていることを確認**
- 単一検索・複数検索：一致（slr0338 の行のみ、上記のずれによる差）

### 相同タンパク質が複数ある場合
1つの試料に相同タンパク質が複数あるとき（Arabidopsis の628遺伝子が該当）、旧サイトは保存順で最後の1件だけを表示していた。
新しいコードも同じものを選ぶようにして、本番と一致させた（全件を表示する改善は今後の検討事項）。
